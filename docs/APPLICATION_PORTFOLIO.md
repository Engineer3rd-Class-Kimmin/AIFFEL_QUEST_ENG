# 교육 과제에서 확인한 문제 해결과 평가

## 목적과 접근

AIFFEL 과정에서 Python, 데이터 분석, 컴퓨터 비전, NLP, LLM, 배포 과제를 노트북으로 작성하고 피어리뷰를 남긴 저장소다. 하나의 완성된 제품으로 묶어 설명하기보다 각 과제의 코드와 결과를 구분한다. 공동 과제와 리뷰어의 글을 모두 개인 산출물로 주장하지 않는다.

이번 평가에서는 외부 모델·데이터 없이 원본 구현을 실행할 수 있는 Python 과제를 선정했다. 회문 판별, 회문 분류, 최솟값·최댓값 클로저, 계좌 객체, 캐릭터 피해 처리를 대상으로 정상·경계·오류 입력을 구성했다. 코드와 리뷰 기록으로 확인되는 구현을 기여 근거로 연결하며, 정확한 페어 작업별 코드 분담을 확인하지 못한 부분은 개인 단독 구현으로 단정하지 않는다.

## 새 평가 결과

35건 중 31건 통과, 4건 실패했다. 빈 목록의 회문 비율에서 ZeroDivisionError가 발생하고, 빈 최솟값·최댓값은 무한대를 반환했다. 음수 출금은 잔액을 증가시키고, 0원 출금은 거래 이력에 기록되는 문제도 관측했다. 빈 입력 거부와 0 이하 출금 무효화는 이번에 추가한 견고성 기준이며 과거 수업의 공식 채점 기준이라고 주장하지 않는다.

[평가셋·입력별 결과](../evaluation/portfolio-v1/RESULTS.md), [실행 원본 JSON](../evaluation/portfolio-v1/results.json), [실행기](../evaluation/portfolio-v1/run.py)를 제공한다. 원본 노트북을 수정하지 않고 함수·클래스 정의만 읽어 실행했다. 입력 대기·학습·외부 전송이 포함된 셀 전체는 실행하지 않았다. CV/NLP/LLM을 포함한 전체 교육 과정의 성능 점수가 아니다. [노트북 24개 인벤토리](../evaluation/portfolio-v1/notebook_inventory.json)에 이번 실행 여부와 기존 오류 출력 수를 별도로 기록했다. 저장되어 있던 오류 출력은 현재 재실행에서 발생한 실패와 구분한다.

## AI 활용과 검증

이번 설명 문서·평가셋·실행기는 Codex로 작성했다(ai-assisted). 합성 입력과 고정 기대값을 원본 코드의 실행 결과에 대조했고 실패도 함께 남겼다. 과거 각 노트북 작성 때 AI를 얼마나 사용했는지 일관된 기록이 없으므로 사용하지 않았다고도, 모두 사용했다고도 단정하지 않는다.

이 평가는 코드를 본 뒤 작성한 개발 진단이다. 독립 평가자의 블라인드 검토나 모델 일반화 평가는 아니다. 다음 개선은 입력 검증과 상태 보존을 명시적으로 구현하고 동일 평가셋으로 전후 결과를 비교하는 일이다. 이번 변경은 과제 원본을 유지해 관측된 한계가 보이도록 했다.

## 공개 범위

신규 평가에는 실제 계정, 거래 데이터, 개인 정보 대신 합성 문자열과 숫자를 사용했다. 피어리뷰 문서는 기존 상태를 유지했다. 기존 저장소의 모든 파일을 비식별 검토했다는 뜻은 아니다.
