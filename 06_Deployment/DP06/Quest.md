# 각 섹션 체크포인트 답변  

## 섹션 1 체크포인트

Q1. 인증 없는 API가 위험한 이유를 두 가지 이상 설명하세요.  

인증이 없으면 누구나 API를 호출할 수 있기 때문에 무단 사용이 발생할 수 있습니다.  

또한 악의적인 사용자가 대량의 요청을 보내 서버 자원을 소모시키거나 서비스 장애를 발생시킬 수 있습니다.  

누가 요청을 보냈는지 식별하기 어려워 문제가 발생했을 때 사용자를 추적하거나 차단하기도 어렵습니다.  

Q2. API Key 방식이 ML 추론 API에 적합한 이유는 무엇입니까?  

API Key 방식은 구현이 간단하고 요청마다 키를 확인하여 허가된 사용자만 API를 사용할 수 있게 할 수 있습니다.  

사용자별로 키를 발급하면 사용량을 추적하거나 특정 사용자의 접근을 차단하는 것도 가능하기 때문에   

ML 추론 API의 기본적인 인증 방식으로 사용하기 적합합니다.  

## 섹션 2 체크포인트  

Q1. Header(None)에서 None은 어떤 상황에서 x_api_key에 들어갑니까?  

클라이언트가 요청을 보낼 때 해당 API Key 헤더를 보내지 않은 경우 x_api_key에 None이 들어갑니다.  

즉 API Key 헤더가 없는 요청을 처리하기 위한 기본값입니다.  

Q2. Depends(verify_api_key)를 엔드포인트에 추가하면 요청 처리 흐름이 어떻게 바뀝니까?  

엔드포인트의 실제 코드가 실행되기 전에 verify_api_key 함수가 먼저 실행됩니다.   

이 함수에서 API Key가 올바른지 검사하고, 인증에 성공하면 엔드포인트가 실행됩니다.  

인증에 실패하면 예외가 발생하여 엔드포인트의 실제 로직은 실행되지 않습니다.  

Q3. 인증 실패 시 반환하는 HTTP 상태 코드 401의 의미는 무엇입니까?  

HTTP 401은 요청한 사용자의 인증 정보가 없거나 유효하지 않아 요청을 처리할 수 없다는 의미입니다.   

즉 올바른 인증 정보가 필요하다는 것을 클라이언트에게 알려주는 상태 코드입니다.  

## 섹션4 체크포인트  

Q1. UploadFile과 Base64 방식의 핵심 차이는 무엇입니까?  

UploadFile은 파일을 multipart/form-data 형식으로 직접 전송하는 방식이고,  

Base64는 파일의 바이너리 데이터를 문자열로 변환하여 JSON 등에 포함해 전송하는 방식입니다.   

Base64는 인코딩 과정에서 데이터 크기가 증가하는 반면 UploadFile은 파일을 직접 처리할 수 있어 파일 업로드에 더 효율적입니다.  

Q2. file.content_type으로 타입을 검증하는 이유는 무엇입니까?  

업로드된 파일이 서버에서 허용하는 파일 형식인지 1차적으로 확인하기 위해 사용합니다.  

예를 들어 이미지 API에 text/plain과 같은 명백히 잘못된 파일이 들어오는 것을 차단할 수 있습니다.  

다만 content_type은 위조될 수 있기 때문에 실제 이미지인지 확인하기 위해 PIL 등의 추가적인 디코딩 검증도 필요합니다.  

Q3. 파일 크기를 제한하지 않으면 어떤 문제가 발생할 수 있습니까?  

사용자가 지나치게 큰 파일을 업로드하면 서버의 메모리, 디스크, 네트워크 등의 자원을 과도하게 사용할 수 있습니다.  

여러 개의 대용량 파일 요청이 동시에 발생하면 서버 성능이 크게 떨어지거나 서비스 장애로 이어질 수 있으므로 최대 파일 크기를 제한해야 합니다.  

## Day 6 최종 체크포인트  

Q1. API Key 인증이 없으면 어떤 위험이 있습니까? (두 가지 이상)  

누구나 API를 무단으로 사용할 수 있으며, 악의적인 사용자가 대량의 요청을 보내 서버 자원을 소모시키거나 서비스 장애를 일으킬 수 있습니다.  

또한 요청자를 식별하기 어려워 문제가 발생했을 때 추적하거나 특정 사용자를 차단하기 어렵습니다.  

Q2. Depends(verify_api_key)는 엔드포인트 실행 전에 어떤 일을 합니까?  

요청에 포함된 API Key를 검사하여 인증된 요청인지 확인합니다.  

올바른 API Key이면 엔드포인트를 실행하고, 인증에 실패하면 HTTP 예외를 반환하여 엔드포인트의 실제 로직이 실행되지 않도록 합니다.  

Q3. UploadFile 방식이 Base64보다 편리한 점은 무엇입니까?  

파일을 Base64 문자열로 변환할 필요 없이 multipart/form-data 방식으로 직접 전송할 수 있습니다.  

따라서 데이터 크기가 불필요하게 증가하지 않고 FastAPI에서 파일명, MIME 타입 등의 파일 정보도 편리하게 처리할 수 있습니다.  

Q4. 파일 업로드 시 크기 제한을 하지 않으면 어떤 문제가 생깁니까?  

매우 큰 파일이나 다수의 대용량 파일이 업로드되면 서버의 메모리, 디스크 및 네트워크 자원이 과도하게 사용될 수 있습니다.  

이로 인해 서버 성능 저하나 서비스 장애가 발생할 수 있으므로 파일 크기를 제한해야 합니다.  

Q5. 이미지를 28×28 그레이스케일로 변환하는 이유는 무엇입니까?  

사용하는 MNIST 모델이 28×28 크기의 그레이스케일 이미지를 입력으로 학습했기 때문입니다.  

업로드되는 이미지의 크기와 채널을 모델이 학습한 입력 형식과 동일하게 맞춰야 정상적인 추론을 수행할 수 있습니다.
