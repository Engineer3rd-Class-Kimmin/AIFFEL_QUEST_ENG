# 각 섹션 체크포인트 답변  

## 섹션 1: Streamlit 소개  

Q1. Streamlit의 스크립트 재실행 모델이란?  

사용자가 버튼을 누르거나 입력값을 변경하는 등 위젯과 상호작용할 때마다 Streamlit이 Python 스크립트를 위에서 아래까지 다시 실행하는 방식입니다.  

Q2. st.text_input()에 값을 입력하면 내부적으로 어떤 일이 일어납니까?  

입력값이 변경되면 Streamlit이 스크립트를 다시 실행하고, st.text_input()은 사용자가 입력한 현재 값을 반환합니다. 이후 코드가 새로운 입력값을 기준으로 다시 실행됩니다.  

Q3. st.set_page_config()를 스크립트 중간에 호출하면 어떻게 됩니까?  

페이지 설정은 일반적으로 Streamlit 코드의 초기에 호출해야 합니다.   

다른 Streamlit 명령 이후에 배치하면 페이지 설정과 관련된 문제가 발생할 수 있으므로 스크립트 상단에 두는 것이 좋습니다.  

## 섹션 2: 핵심 컨셉  

Q1. st.file_uploader()로 업로드된 파일의 바이트 데이터는 어떻게 얻습니까?  

업로드된 객체에서 getvalue()를 사용하면 됩니다.   

uploaded_file = st.file_uploader("이미지 업로드")  

if uploaded_file:  
    image_bytes = uploaded_file.getvalue()  

Q2. Streamlit에서 @st.cache_resource를 사용하는 이유는 무엇입니까?  

API 클라이언트처럼 매번 새로 생성할 필요가 없는 리소스를 캐시에 보관하여 Streamlit이 재실행될 때마다 반복 생성하지 않도록 하기 위해 사용합니다.  

## 섹션 3: System Architecture  

Q1. 모놀리식과 분리 아키텍처의 핵심 차이를 한 문장으로 설명하세요.  

모놀리식 구조는 화면과 모델 추론 기능이 하나의 애플리케이션에 포함되고, 분리 아키텍처는 Streamlit 프론트엔드와 FastAPI 백엔드를 각각 독립적인 서버로 분리합니다.  

Q2. 모델을 업데이트할 때, 분리 아키텍처에서는 어떤 서버만 재배포하면 됩니까?  

모델을 관리하고 추론을 수행하는 FastAPI 백엔드 서버만 재배포하면 됩니다.  

Q3. Streamlit 앱에 PyTorch가 설치되어 있지 않아도 되는 이유는 무엇입니까?  

Streamlit은 직접 모델을 실행하지 않고 FastAPI 서버에 HTTP 요청만 보냅니다. 실제 PyTorch 모델 로딩과 추론은 FastAPI 서버가 담당하기 때문입니다.  

## 섹션 4: API 호출  

Q1. 이미지를 API에 전송할 때 Base64로 인코딩하는 이유는 무엇입니까?  

이미지 파일은 바이너리 데이터이므로 그대로 JSON에 넣을 수 없습니다. 따라서 이미지 바이트를 Base64 문자열로 변환하여 JSON 데이터 안에 담아 전송합니다.  

image_base64 = base64.b64encode(image_bytes).decode("utf-8")  

Q2. response.raise_for_status()는 어떤 역할을 합니까?  

HTTP 응답 상태가 오류인지 확인합니다. 4xx나 5xx 오류가 발생했다면 예외를 발생시켜 try/except에서 오류를 처리할 수 있도록 합니다.  

## 섹션 5: 최종 실습  

Q1. API 호출 실패 시 사용자에게 스택 트레이스가 아닌 메시지를 보여줘야 하는 이유는 무엇입니까?  

일반 사용자는 Python 스택 트레이스를 이해하기 어렵기 때문에, 오류 원인과 해결 방법을 알기 쉬운 메시지로 안내해야 합니다.  

Q2. st.session_state에 결과를 저장하는 이유는 무엇입니까?  

Streamlit은 버튼 클릭이나 입력 변경 때마다 전체 스크립트를 다시 실행하기 때문에 일반 변수에 저장한 결과가 사라질 수 있습니다.   

st.session_state를 사용하면 재실행 후에도 값을 유지할 수 있습니다.  

st.session_state["last_result"] = result  

Q3. 이미지를 API로 전달할 때 Base64 인코딩이 필요한 이유는 무엇입니까?  

이미지의 바이너리 데이터를 JSON에서 전송 가능한 문자열 형태로 바꾸기 위해서입니다.  

노트북 맨 아래의 Day 4 최종 체크포인트 7문제만 제출용으로 아주 짧게 적으면 다음처럼 쓰면 됩니다.  

Streamlit의 스크립트 재실행 모델이란?  

→ 사용자가 위젯과 상호작용할 때마다 Python 스크립트 전체가 위에서 아래로 다시 실행되는 방식이다.  

@st.cache_resource를 사용하는 이유는?  

→ API 클라이언트와 같은 리소스를 캐시하여 스크립트가 재실행될 때마다 다시 생성하지 않기 위해 사용한다.  

프론트엔드와 백엔드를 분리하는 핵심 이유 두 가지는?  

→ UI와 모델 추론 기능을 독립적으로 관리할 수 있고, 한쪽을 수정하거나 배포할 때 다른 쪽에 미치는 영향을 줄일 수 있다.  

Streamlit 앱에 PyTorch가 필요 없는 이유는?  

→ 모델 추론은 FastAPI 서버가 담당하고 Streamlit은 HTTP 요청과 결과 표시만 담당하기 때문이다.  

API 호출 실패 시 스택 트레이스가 아닌 메시지를 보여줘야 하는 이유는?  

→ 사용자가 오류 원인과 해결 방법을 쉽게 이해할 수 있도록 하기 위해서이다.  

st.session_state에 결과를 저장하는 이유는?  

→ Streamlit 스크립트가 재실행되어도 이전 추론 결과를 유지하기 위해서이다.  

이미지를 API로 전달할 때 Base64 인코딩이 필요한 이유는?  

→ 바이너리 이미지 데이터를 JSON으로 전송할 수 있는 문자열 형태로 변환하기 위해서이다.
